# F-001: Composite HID configuration protocol and macOS authorization boundary

- status: validated
- evidence: E-001, E-002, E-003, E-004
- path_type: callflow

`Keyboard Studio → IOHIDCheckAccess → IOHIDManager(8089:000C, FF00:01) → report 02 framing → command 22 key map → command 04 guarded flash commit`

The second keyboard can be customized without a vendor web application. Because its vendor and keyboard collections share one composite descriptor, macOS Input Monitoring authorization is required even though the app opens only vendor reports. The application exposes this boundary explicitly and does not attempt a write until the user presses Save.
